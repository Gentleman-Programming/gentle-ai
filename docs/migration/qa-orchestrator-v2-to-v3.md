# Inventario: migración del QA-Orchestrator v2 hacia v3.7.0

**Fecha:** 2026-09-23
**Rama investigada (v2 legacy):** `legacy-v2-custom` (= tag `custom-v2-final`, commit `9e0b5679` "fix(qa-verify): restore byte-parity between skills/ and internal/assets/skills/")
**Rama base (v3):** `v3.7.0` (commit `6dee8f83` "Merge pull request #4912 from Gentleman-Programming/feat/claude-native-rdd-models")
**Estado del trabajo:** solo lectura/investigación — ningún archivo de código fue modificado.

## Contexto

El fork divergió de upstream en `v2.3.0-rc.2` y acumuló 124 commits propios construyendo un QA-Orchestrator: cuatro verbos CLI (`qa-begin`, `qa-finish`, `qa-approve`, `qa-status`, más `qa-validate`) respaldados por un ledger propio (`internal/qastage` + `internal/sddstatus.OpenRuntimeStore`/`StageVocabulary`), y seis skills (`qa-supervisor`, `qa-explore`, `qa-spec`, `qa-apply`, `qa-verify`, más un archivo de reglas compartido `qa-gate-policy.md`). Mientras tanto, upstream avanzó 1665 commits hasta `v3.7.0` y reconstruyó buena parte de la infraestructura equivalente bajo nombres distintos: ODD (`odd/tasks/*.md`), SDD (fases explore/propose/spec/design/tasks/apply/verify/archive, implementadas como plantillas de agente generadas por `internal/components/sdd/*.go`, no como `skills/*.md` estáticos), Engram (memoria persistente vía MCP), y RDD (revisión automatizada por "lenses" en `internal/reviewtransaction`, `internal/reviewerprovider`, comando `gentle-ai review inspect-candidate --lens ...`).

**Verificación clave:** en `v3.7.0` no existe el paquete `internal/qastage`, no hay ningún verbo `qa-*` registrado en `internal/app/app.go`, y ninguna referencia a BookStack existe en el árbol (`git grep -il bookstack v3.7.0` no devuelve resultados). Los 6 archivos `skills/qa-*` y `skills/_shared/qa-gate-policy.md` son 100% líneas nuevas frente a `v3.7.0` (`git diff --stat v3.7.0 legacy-v2-custom -- skills/qa-*` → solo inserciones, 443 líneas, 0 delecciones/reemplazos).

## Preguntas abiertas para el usuario

1. **Vocabulario de stages (fila 5):** ¿se reintroduce un mecanismo `StageVocabulary` genérico dentro de `internal/sddstatus` actual (para que QA y SDD compartan el mismo motor), o el ledger QA se reconstruye como algo aparte, aceptando divergencia con el runtime SDD de `v3.7.0`?
2. **Gate de aprobación humana pre-apply (filas 3, 8, 9):** ¿el mecanismo de `consent_contract.go`/`edit_authority.go` (pensado para aprobar acceso de escritura a rutas) se extiende para aprobar "contenido de una etapa", o se necesita un contrato de consentimiento nuevo y paralelo?
3. **BookStack y GitLab MCP:** el fork depende de estos dos MCP en 4 de las 5 skills sub-agente. ¿Siguen siendo la fuente de verdad de negocio que el usuario quiere conservar, o se evalúa reemplazarlos por Engram/ODD como fuente única (dado que upstream no tiene tracción con BookStack en absoluto)?
4. **`ErrRuntimeStageApprovalRequired`/`ErrRuntimeStageOutOfOrder`:** confirmado que no existen en `v3.7.0`. ¿Se prioriza recrearlos como tipos de error específicos del ledger QA, o se opta por un mecanismo de gate distinto (p. ej. delegando en RDD/lens)?
5. **`qa-verify` vs. lens de RDD:** dado que `v3.7.0` ya tiene un sistema de revisión automatizada por lens bastante más riguroso (`internal/reviewtransaction`), ¿vale la pena rediseñar `qa-verify` para invocar ese sistema en vez de mantener un checklist narrativo propio? (Nota: esto es una pregunta de diseño, no una propuesta — se deja fuera del alcance de este inventario según las reglas de la tarea.)
6. **Screenplay+POM / Playwright / locator-hunting:** estas convenciones son 100% específicas del stack QA de este cliente y no tienen ningún artefacto equivalente en `v3.7.0`. ¿Se documentan como una extensión de dominio sobre el flujo SDD genérico, o se mantienen como una familia de skills separada (como hoy)?
7. **Tests de `internal/qastage` (433+83+107 líneas) y de `internal/cli/qa_*_test.go` (~650 líneas):** si se opta por PORTAR/ADAPTAR el ledger, ¿se migran estos tests tal cual (adaptándolos a la nueva forma del `runtime_ledger.go` de 919 líneas), o se reescriben desde cero contra el diseño que se decida?
