# Atomic PNPM publication

`PublishNativePNPMInstallationWithExperience` consumes original producer DATA through the verified staging operation, copies the trusted current supervisor and publishes a Separate manifest. Passing nil retains the unprofiled publication case without a duplicate wrapper. It reuses the npm flow's final write/binding/identity/recheck/rename-no-replace/directory-sync/readback helper. Only successful final-root readback returns `ComponentInstalled`; failures after rename remain uncertain and preserve the destination for inspection.

The caller retains the qualified private boundary and source custody. Existing destinations are never replaced. The source is not installed again or modified. The ordinary installer coordinator uses this boundary only after the sealed producer terminates; `ComponentInstalled` here establishes payload publication, not complete MVP acceptance.

Run `go test -tags=shell_pnpm_publication -run '^TestUserPNPMPublish' ./internal/shellinstaller` in the qualified original-DATA fixture, then the default package suite. The public API test checks authentic publication, occupied/canceled destinations, seal rejection and unchanged original DATA. A deliberately incomplete fixture exercises post-rename failure at the shared commit boundary without repeating the full payload copy.

## Supervised launchers

PNPM publications bind `pi` and `gentle-shell` to distinct roles through `shell launch-pnpm ROOT ROLE`. The ordinary CLI and Linux worker retain kernel qualification, manager delegation and process-group cleanup. Authenticated persistent Node executes the checked entrypoint; private runtime environment values replace caller injection. Direct Pi uses the retained agent directory, while Shell preserves its isolated default under private HOME. The complete manifest/code seal is checked before and after execution. Existing npm bindings and `launch` semantics remain unchanged.

For real execution proof, build the ordinary supervisor inside the qualified sandbox, mount it read-only as `/qualified-supervisor`, and run tagged `TestUserPNPMLaunchPrepare` with private persistent `/fixture` and original `/out` read-only. In a second qualified run, mount the same `/fixture`, omit `/out` entirely, and run exactly `TestUserPNPMLaunch`. Both final scripts must pass version/help with hostile caller Node/agent variables; code and caller-project bytes remain unchanged. This is launcher qualification, not TUI or three-platform installed acceptance.

## Existing PNPM destinations

A confirmed `RunUserInstall` request for an existing PNPM destination returns its authenticated installation after complete manifest, identity, binding and code-seal readback. It does not enter npm provisioning or rerun suppliers. Existing npm verification is unchanged. Stale physical confirmation and damaged PNPM code remain rejected without repair or replacement.

Run `go test -tags=shell_pnpm_publication -run '^TestUserPNPMResume$' ./internal/shellinstaller` in the qualified original-DATA fixture. It publishes the authentic payload once, then checks public resume, unchanged installed data, stale confirmation and unsealed-code refusal. This is resume coverage, not fresh original-producer or TUI acceptance.

## Original producer transaction

`NativeInstallerRuntime.produceForDestination` runs the original `Prepare` and `RunWithLocation` phases and returns their result and location, not publication authority. It requires an already snapshot-bound private worker, current physical destination confirmation and a fresh Separate target with its complete supported experience profile. It rechecks confirmation after the original run; blocked results retain the original verdict and no location. Caller-owned producer evidence survives failures. After source and confirmation checks, a private runtime copy selects an owned `data` directory for XDG data so publication and final launch use the same location; existing transport callers keep their original data home. Runtime pools use explicit single-worker settings rather than inherited caller options. The private environment declares `/usr/bin/bash` so the original PNPM PATH-persistence step can identify its shell without inheriting the caller shell.

The fresh transaction test explicitly composes that producer with the canonical request and `PublishNativePNPMInstallationWithExperience`; the superseded in-process `InstallToDestination` composite is retired. The caller still supplies authenticated temporary Node and immutable source custody. This fixture does not qualify the ordinary route's sealed-process termination and receipt boundary or acquire a production source carrier. Installer source is independent of `SDKSource`. The private qualification uses local Shell revision `8983b43bd52210a9242a056d291fb2bf30e73cc5`, not an assertion that this revision is published. The cleanup preserves the scenarios and limits below without rerunning their Guest proofs.

For fresh qualification, run tagged `TestUserNativeInstallPrepare` once against a new owned `/producer` and the exact protected `/native-source.zip`. Then bind both retained archive metadata and extracted source read-only and run exactly `TestUserNativeInstallFresh` with real DNS/CA/network, hidden system Node and unchanged limits. Producer output stays outside the capped tmpfs; publication stays within it at the fresh `/tmp/native-publication` fixture. Settled sandbox teardown disposes of this fixture; the test does not recursively delete the large payload before reporting its result. All assertions and execution limits remain unchanged. Never substitute retained successful DATA for this fresh transaction test. Default rejection tests use `-tags=shell_native_install -run '^TestUserNativeInstall'`. A successful transaction does not establish TUI, launcher or three-platform acceptance.

### Base preferences in PNPM publication

`PublishNativePNPMInstallationWithExperience` applies the existing canonical
persona/background writer to the copied unpublished stage. Passing nil to this
same boundary retains the unprofiled behavior. Existing selected files are never overwritten;
unmanaged persona leaves its preimage alone. Unsupported optional effects fail
before staging. This does not establish ordinary TUI or installed acceptance.
The retained-package consumer cases run individually in qualified sandboxes:
`go test -mod=readonly -p=1 -count=1 -timeout=110s -tags=shell_pnpm_publication -run '^TestUserPNPMExperience$/^neutral-off$' ./internal/shellinstaller`
Repeat for `gentleman-on` and `unmanaged-off`; run refusal and legacy publication
regressions separately, without increasing the shared resource limits.

### Descriptor-rooted Linux inventory

Linux PNPM inventories resolve regular files beneath one no-symlink directory
handle. They retain complete content hashes, ownership and mode checks, size
bounds, cancellation, and before/after physical identities. Unsupported kernels
use the existing guarded reader. The generic native reader is unchanged.

Enumeration is not an atomic snapshot: immutable source custody and the complete
source/destination inventory comparisons remain required. A DATA-only measurement
produced the same 84,341-entry inventory in 10.165s versus 21.077s before this
change; these single measurements do not establish full installation timing.
