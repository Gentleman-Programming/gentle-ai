# Protected original-installer coordinator

The Linux amd64 internal coordinator accepts only a confirmed fresh Separate selection, a private empty workspace beside the destination, an absent sibling stage and a bounded inherited deadline. Internal selectors do not grant execution authority.

Kernel readback requires the coordinator to be in the existing capped operation aggregate with full identity maps. It prepares pinned temporary Node and the embedded original source, then launches the sealed producer in that same aggregate with the original deadline unchanged.

The sealed producer writes an exclusive 0600 locator receipt bounded to 64 KiB, preserving the original raw result and action. That DATA is not publication authority. After physical producer termination, the full-map coordinator rechecks confirmation and operation membership, authenticates the payload, and publishes with the unchanged root/current-user supervisor ownership policy. It never accepts unmapped ownership as provenance.

The producer must settle physically before cleanup runs inside the capped coordinator. Invalid path/preimage/deadline inputs refuse without preparing files. Shared and existing destinations are not coordinator selections.

`TestUserNativeCoordinatePrivate` requires the existing isolated private-manager fixture; it verifies actual aggregate membership and rejects wrong prefix, wrong stage, nonempty and symlink workspaces. Ordinary entry ownership and whole-install/TUI acceptance are separate from this internal coordinator unit.
Base persona and background preferences are not written into the original producer.
The complete profile remains bound to physical confirmation and is materialized
once in the unpublished final stage. Existing preference collisions still refuse;
legacy preparation keeps its original behavior.
