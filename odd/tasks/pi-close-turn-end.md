# Close step for every runtime: end-of-turn condition before the report format
Branch `fix/pi-close-turn-end` from main `c26d38c04` (contract 1.6.0). Consumer-side spec and evidence: gentle-pi `odd/tasks/turn-end-coherence.md` (S8, L8, L10, L13), branch `feat/turn-end-coherence`. Local commits only; issue, PR and merge are handled by the parent session.

## Specs
S1. Approved plan, step 6: "Separar en Close «terminar el turno» de «cerrar la entrega». La condición para cerrar va primero; el formato del informe, después." Problem observed in the field with GPT models on Gentle Shell: the Pi step 7 opens with "Report the verified outcome, every failed, skipped, or pending check, and the next step." and says "an unavailable verifier or subagent is reported as unavailable, never retried", which reads as the format for ending a turn after an ordinary failed attempt.

S2. New step 7 for the Pi routing block (`piODDSteps` in `internal/components/agentguidance/routing.go`). Starting draft, to adjust only where a test or a clearer wording requires it:
> 7. **Close.** Close only when no runnable authorized step remains. A failed attempt with a permitted route left is an obstacle. Report the verified outcome, every failed, skipped, or pending check, and the next step. Diagnose, fix, and rerun failed checks within their limits. An applicable quick check runs once; an unavailable verifier or subagent is reported as unavailable, never retried or escalated into extra ceremony. A wait is launched work whose completion wakes you without asking the human. Only a wait, a real human decision, the user's explicit stop, a denial, missing consent, an exhausted limit, or a failure with no permitted route left can end the turn with unfinished work. Mark only the affected work incomplete for that failure, pending otherwise; independent authorized work continues. Never abandon runnable work or present an unverified outcome as final. Before writing `Risk: none`, check whether your diff changes code that existing behavior the request did not mention also uses (shared options, parsers, helpers); if it does, that is item 3. Missing, partial, unavailable, or declined proof forbids claiming completion of the affected work, never an independently authorized next step, while a required authorized check the existing budget still allows keeps running; stop checking only inside an exhausted or denied boundary or with no permitted route left, report that exact blocker and the decision that is genuinely the human's, and never invent a pass. Never turn a report into a blind self-reprompt loop. Hedged wording is not a stop. The native review candidate is a work-unit commit or a PR slice, never a TODO checkbox and never the accumulated feature branch; native review runs only under the user-owned RDD switch.
Required properties: the closing condition comes before the report format; a failed attempt with a permitted route left is an obstacle, not a close; a check that ran and failed (diagnose, fix, rerun within its limits) is distinct from a verifier or subagent unavailable as a capability (reported, never retried); the list of what ends work with something unfinished also admits a failure with no permitted route left; "wait" names launched work whose completion resumes the turn; the `Risk: none` sentence, the proof clauses, "Never turn a report into a blind self-reprompt loop", "Hedged wording is not a stop" and the native review candidate sentence stay. The step is byte-neutral or smaller than the current one (1,778 bytes with its newline).
