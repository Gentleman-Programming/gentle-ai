# #4670 — RDD-off mode resolution must not validate RAR authority on SMB/UNC

Objective: `review mode status` and `review stop-hook` succeed when RDD is off, and an unsupported (UNC/unknown) authority filesystem yields a typed refusal with a documented continuation.
Branch: `fix/4670-rdd-off-unc` (worktree `/home/gentleman/work/gentle-ai-4670`, base `origin/main` 4b65ee67). Delivery: `ask-on-risk`. Runner: `go test ./internal/reviewtransaction/... ./internal/cli/...` (focused with `-run`), full `go test ./...`.

## Specs

- **S1** Issue expectation 1 (verbatim): "When the effective RDD mode is `off`, mode resolution should complete without validating the RAR authority path. There is no authority to establish, so an unsupported-filesystem classification should not be reached and the stop hook should be a no-op." Concretely (design B, see L3): when the global mode is off, `ResolveRDDMode` (internal/reviewtransaction/rdd_mode.go ~:293) still tries to read the clone-local override so status reports both sources truthfully, but if that read fails for any reason it degrades to `off (decided by global)` with a nil error (clone-local can only disable, so the effective result cannot change); this degradation never applies when the global mode is on or unset; normal local repos stay byte-identical; `gentle-ai review mode status` exits 0 printing `off (decided by global)`; `gentle-ai review stop-hook` is silent and returns nil.
- **S2** Read path with no stored override: `cloneLocalRDDModeRoot(create=false)` / `cloneLocalRDDModeReadRoot` checks with `Lstat` whether the switch directory (and the legacy path) exists before `ensureRARSwitchRoot` validates the Git common dir; when none exists it reports "no override" without validating the parent. Fail-closed is preserved for any path that does exist or for writes.
- **S3** Issue expectation 2 (verbatim): "For a genuinely remote SMB/UNC Git common directory, the refusal should carry a typed unsupported-filesystem result with a documented continuation, rather than a bare error whose remediation text (\"check the path and rerun\") cannot resolve a correct path." Export a typed error in `reviewtransaction` (e.g. `UnsupportedAuthorityFilesystemError{Path, Remote bool}`) reachable with `errors.As`, still wrapping the existing unsafe-path sentinel so #1918 fail-closed semantics hold; map it in `review mode` (`reviewModeUnreadable`/`reviewModeUnsafePathRefusal`, following `reviewModePrivateModeIneffectiveError`) to a message whose continuation names `gentle-ai review mode disable --scope global` or moving the repository to a local NTFS/ReFS volume. The stop hook with this typed error does not fail every turn.
- **S4** When resolution fails, `review mode status` must not print the misleading `off (decided by clone_local)` line next to `clone-local: unset`; mark the mode as unavailable instead.
- **S5** Tests (RED first): `internal/cli/review_stop_hook_test.go` variant of `TestReviewStopHookSilentWhenRDDOff` with an unvalidatable common dir + global off → silent, nil (add an injectable seam for `validateRARRepositoryParent` if needed); `internal/cli/review_mode_test.go` mode status global off + invalid common-dir parent → exit 0, "off (decided by global)"; `internal/reviewtransaction/rar_path_safety_windows_test.go` UNC `\\server\share\repo\.git` → typed error via `errors.As` (must compile under GOOS=windows: run `GOOS=windows go vet ./internal/reviewtransaction/...` or `go test -c`); unit test that `ResolveRDDMode(global=off)` succeeds with off/global when the common dir cannot be validated (and still fails when global is unset). Existing behavior pinned: default-on with an existing override still fails closed on an unsafe parent.
