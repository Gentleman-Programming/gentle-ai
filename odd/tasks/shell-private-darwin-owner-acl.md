### Native fixture and success criteria (fail closed on every ambiguity)

1. Use a disposable, unique directory under `/tmp` (not an actual home); clean up. Verify its traversable ancestors and fixture identity. Install an inheritable `everyone` **allow read/write** ACE on the parent. Create a child empty regular inode via `O_CREAT|O_EXCL|O_NOFOLLOW` (and close-on-exec), requested mode `0600`, retain its fd. Require `fstat` owner=current UID and exact mode `0600`, record dev/ino; verify path still denotes this held inode without following links. Never use path-based child ACL reads as a replacement for same-fd reads.
2. On that **same fd**, before replacement, require a nonNULL `acl_get_fd_np` and unambiguous, exhaustive ACE enumeration establishing inherited `everyone` allow read/write on the actual child (tag/qualifier, flags and permissions), not merely the parent or `ls -le` text. Check each API return and errno. Apple `acl_get_entry(3)` returns **0 for an entry and -1 for error**: never treat -1 as normal end-of-list, invent an indexed-success convention, or silently treat `ENOENT` as absence. If no documented, reliable way to prove the exact count/end exists on the native runner, **BLOCK**, do not infer safety from text output.
3. Map the **current owner UID** to UUID with `mbr_uid_to_uuid`, require success and nonambiguous match with the fd owner. Construct an explicit **nonempty** extended ACL containing exactly one owner-UUID allow ACE for read/write (no `everyone`, no group, no inherited flags or other ACEs). Apply with `acl_set_fd_np` to the *same fd*; require success. Re-read from that fd with nonNULL `acl_get_fd_np` and prove exactly one allow ACE, owner UUID, expected permissions and flags, no inherited/world or extra entries. Fail on NULL even with `ENOENT`, any errno, unverifiable end-of-entries or partial readback. Require unchanged owner, mode `0600`, dev/ino and child path-to-fd identity before and after. No empty-ACL clearing inference.
4. **Only after** the held-fd pre/post proof, write a synthetic, disposable marker into the child and close/flush as needed; never write real private content. Via CI passwordless `sudo -n -u <identity>` choose and verify a *truly distinct, unprivileged, nonroot* UID, prove it can traverse the parent/ancestors and open a separate readable control file there (so denial is not just a blocked parent or broken probe). From that identity attempt actual child `O_RDONLY` and `O_WRONLY` opens without reading out or modifying marker bytes; require permission-denied for both, distinguish all other errors. If `sudo -n`, a suitable identity, traverse/control probe, or either child-open observation is unavailable/ambiguous, FAIL as **BLOCK/inconclusive**, never SKIP or PASS confidentiality. No `testing.Short()` skip may turn absence of a nonowner probe into success in the opted-in native lane.

## Source basis and previous negative evidence

- Prior isolated empty-ACL fork run [36028533361](https://github.com/decode2/gentle-ai/actions/runs/36028533361) at `bdc62d79`: inherited `everyone` read/write appeared on a mode-0600 empty inode; `acl_set_fd_np(empty)=0`; same-fd `acl_get_fd_np(after)=NULL` with `ENOENT` was ambiguous; **no nonowner proof**. Do not recycle that result as proof of replacement or confidentiality.
- Apple [acl_set(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_set.3.html) does not promise an empty-set clear proof; `acl_get(3)` ENOENT does not guarantee absence; [acl_get_entry(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_entry.3.html) documents 0=entry, -1=error. [mbr_uid_to_uuid(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/mbr_uid_to_uuid.3.html) provides owner UID→UUID mapping. Native enumeration semantics must be verified rather than guessed.

## Key Learnings

- Native inherited permissive ACL plus mode `0600` is not owner-only proof. Empty ACL setter success followed by NULL/ENOENT readback is inconclusive.
- A positive replacement claim needs same-fd exact ACE readback **and** actual distinct-UID denial with proven parent traversal; any missing precondition blocks the claim.
- Native dispatch-only registration RED and successful non-skipping runtime proof are separate receipts; neither Linux green nor ordinary native refusal CI enables a Darwin writer. A registration commit alone is expected RED, not observed native evidence.
