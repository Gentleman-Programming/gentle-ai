Require `fstat` owner=current UID, exact mode `0600`, dev/ino; verify path identifies the held inode without following symlinks.
2. Before replacement, require nonNULL `acl_get_fd_np` on **that FD** and exhaustive, unambiguous ACE enumeration proving inherited `everyone` allow read/write on the actual child (tag/qualifier, flags, permissions). Check every API return and errno. Apple `acl_get_entry(3)`: **0=entry, -1=error**; never treat -1/`ENOENT` as normal end or invent indexed success. If documented reliable count/end semantics cannot be established on native runner, BLOCK.
3. Map current owner UID to UUID via `mbr_uid_to_uuid`, require success and match to `fstat` owner. Build explicit **nonempty** extended ACL with exactly one owner-UUID allow read/write ACE, no `everyone`, group, inheritance or extras. `acl_set_fd_np` on same held FD; re-read with nonNULL `acl_get_fd_np` on same FD, prove exactly that one owner ACE with expected permissions/flags and no other entries. NULL even with `ENOENT`, partial enumeration or unverifiable end BLOCKS. Verify unchanged owner, exact mode `0600`, dev/ino and path-to-FD identity before/after. No empty-ACL clearing inference or path-only child ACL read.

## Source basis and previous negative evidence

- Prior isolated empty-ACL fork run [36028533361](https://github.com/decode2/gentle-ai/actions/runs/36028533361) at `bdc62d79`: inherited `everyone` read/write appeared on a mode-0600 empty inode; `acl_set_fd_np(empty)=0`; same-fd `acl_get_fd_np(after)=NULL` with `ENOENT` was ambiguous; **no nonowner proof**. Do not recycle that result as proof of replacement or confidentiality.
- Apple [acl_set(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_set.3.html) does not promise an empty-set clear proof; `acl_get(3)` ENOENT does not guarantee absence; [acl_get_entry(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_entry.3.html) documents 0=entry, -1=error. [mbr_uid_to_uuid(3)](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/mbr_uid_to_uuid.3.html) provides owner UID→UUID mapping. Native enumeration semantics must be verified rather than guessed.

- Native dispatch-only registration RED and non-skipping GREEN are separate receipts per selector; neither Linux green nor ordinary refusal CI enables a writer. A RED was observed at `4a4cd8af`; no native A or B post-implementation evidence exists.
