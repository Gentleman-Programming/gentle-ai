## Problem and rationale
V2 deliberately replaces plugin/server APIs and terminal configuration. Our five server plugins and TUI plugin use V1 contracts. Our config/profile/telemetry readers only understand V1 keys; installer advice and CI do not prove V2 compatibility. Supported V1 config and Markdown assets remain accepted upstream, so a wholesale rewrite is unnecessary.

## Constraints
- Preserve V1 behavior and unrelated user configuration; recognize native V2 precedence without creating conflicting shadow settings.
- Keep review evidence, binding, schema, admission, consent, and bounded lifecycle owned by existing Go contracts.
- Preserve exact-answer consent checks; never grant from arbitrary free text or background launch acknowledgements.
- Isolate tests with temporary homes/config/data/service paths. Never launch against ambient user OpenCode state or reuse credentials.
- No global install, automatic data migration, remote execution, or network model calls.
- English artifacts. One writer at a time. Roughly 400 authored lines per task is advisory, not a hard cap.
