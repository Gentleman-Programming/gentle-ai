# Fix #6156: base-ref STATUS fails pre-native when untracked declaration is omitted

Fix the pre-native `operation_failed` / `unrelated target status is inconsistent` failure that `gentle-ai review status --base-ref=<ref>` produces when the untracked declaration flags are absent, which blocks every Gentle Shell pre-delivery preflight.

## Specs

- S1 (issue #6156, Expected behavior): "When the untracked declaration is absent, base-ref STATUS should answer with the typed transition the provider already emits in its other branches — the selectorless `collect`/`intended_untracked_selection_required`, or the `invalid_request` that names the missing flags — instead of a pre-native validation failure whose cause text asserts a target inconsistency that does not exist."
- S2 (issue #6156, Actual behavior table, rows 2-3): `status --base-ref=<ref>` (with/without `--committed-only`) fails `pre_native` with `operation_failed` / `unrelated target status is inconsistent`; `status --base-ref=... [--committed-only] --expected-untracked-inventory=<sha>` (no scope) returns `invalid_request`: `untracked selection requires --untracked-scope and --expected-untracked-inventory`.
- S3 (issue #6156, Impact): "Gentle Shell's pre-delivery preflight derives the exclusion digest by calling `targetStatus({ baseRef, committedOnly, agent })` — precisely the shape that fails — ... the guard cannot self-heal."
- S4 (issue #6156, Minimal reproduction): steps 1-5 (main worktree, one commit ahead, one unrelated untracked file; selectorless STATUS succeeds and prints `eligible_untracked_inventory`; base-ref STATUS fails; adding `--untracked-scope=exclude --expected-untracked-inventory` succeeds with `target_already_acknowledged`).
- S5 (Alan's comment, member): facade `inspect` with `untrackedScope: exclude` failed with the same `validate negotiated review status: unrelated target status is inconsistent`; facade `assess` with explicit base + `committedOnly: true` failed with `untracked files require an explicit declaration`. Expected: "a committed-only candidate with explicitly excluded bookkeeping should be assessable, or return an actionable typed declaration request rather than an inconsistent-authority diagnostic."
- S6 (lalvarez-ai-mate's comment): the digest `eligible_untracked_inventory` from selectorless STATUS is byte-identical to the digest `assess` names in its refusal; base-ref STATUS fails only while the untracked file exists. Confirms the intended fix direction: base-ref STATUS should surface the same inventory/typed transition.
- S7 (martinzarzar's comment, 4.6.0): the same opaque deny occurs with a modified-but-uncommitted tracked file outside the candidate (no untracked files); selectorless raw CLI status succeeds. Root cause unconfirmed; include only if the same code path handles it.
